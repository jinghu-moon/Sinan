# 01 · 标签固定、保护、目录锁定与外观设计

- 项目：TabTail（TT）。
- 日期：2026-11-16。
- 状态：v0.7 已实现阶段 0–4 的代码与交互接口，精确系统版本下实验交付；自动验证与原生入口证据见 [实现状态](implementation.md)，真实输入和视觉验收见 [测试步骤](testing-tab-features.md)。尚未完成的人工验收不计为通过。
- 基础：现有 C++ CLI、后台代理、FTXUI 双语 TUI、标题策略和三模式标签宽度。
- 适用范围：Windows 11 原生 Explorer；每项能力以实际系统版本的适配和验收结果为准。
- 本文中的“背景色”均指**标签背景色**，不指文件列表背景或整个 Explorer 窗口背景。

## 1. 目标与使用场景

用户在 Explorer 中同时打开多个项目目录，希望快速标记重要标签、防止误关闭，并让特定标签始终保持在工作目录。日常操作应在当前 Explorer 内通过快捷键完成，TUI 用于设置、查看状态和批量管理。

固定到 Windows 快速访问侧边栏解决“以后方便打开目录”；本设计解决“保护当前打开的工作标签”。两者独立，TabTail 不修改快速访问记录。

典型流程：在工作标签按固定快捷键，图标变成醒目的图钉，并启用防误关闭；需要保持工作位置时，再按目录锁定快捷键，记录当前目录，图标变成锁；系统通知在状态实际确认后提示操作结果。

## 2. 三种状态的明确语义

### 2.1 固定标签（Pinned）

- 标记当前标签为重要工作标签，默认具有防误关闭效果。
- 首阶段保留标签原位置，不自动左置、不缩成仅图标、不改变宽度模式。
- 固定不阻止导航。需要保持目录时另外启用“锁定目录”。
- 取消固定移除固定带来的关闭保护，保留用户独立开启的保护和目录锁定。
- 状态绑定标签实例。同一目录的两个标签可以分别固定，不能按路径把它们一起标记。

### 2.2 保护标签（Protected）

- 防止误关闭，可独立开启，不要求固定标签。
- 有效关闭保护为 `pinned || protected`。固定存在时不能通过关闭独立保护绕过它。
- TUI 分别显示“固定”“独立保护”和“有效关闭保护”，解释保护来自哪里。
- 关闭受保护标签前，先取消固定并关闭独立保护；正常关闭操作不设计为重复按键即可绕过。
- 首阶段覆盖单标签关闭；整窗关闭、进程退出和系统关机另设能力与边界。

### 2.3 锁定目录（Directory locked）

- 记录启用锁定时的当前目录，阻止当前标签被导航到其他位置。
- 目录锁定与固定、关闭保护独立；只锁定目录不自动增加关闭保护，TUI 明确显示这个区别。
- 同一路径的刷新、排序、视图切换和文件选择继续允许。
- 能可靠转发的用户导航在新标签中打开，原标签保持锁定位置。
- 无法可靠转发时，阻止本次导航并提示；不能先导航离开再返回，造成闪烁或执行了错误位置上的操作。
- 取消锁定保留当前目录；不自动关闭导航期间新开的标签。
- 首版只锁定能取得稳定身份的文件系统目录；虚拟位置能力逐项验证，不支持时说明原因。

### 2.4 组合状态与图标

| 固定 | 独立保护 | 锁定目录 | 关闭行为 | 导航行为 | 默认替换图标 |
| --- | --- | --- | --- | --- | --- |
| 否 | 否 | 否 | 系统行为 | 系统行为 | 原图标 |
| 是 | 否 | 否 | 防误关闭 | 允许 | 图钉 |
| 否 | 是 | 否 | 防误关闭 | 允许 | 原图标 |
| 否 | 否 | 是 | 系统行为 | 保持锁定目录 | 锁 |
| 是 | 任意 | 是 | 防误关闭 | 保持锁定目录 | 锁，固定状态另在提示中表达 |
| 否 | 是 | 是 | 防误关闭 | 保持锁定目录 | 锁 |

单个图标位置不堆叠两个符号。固定与锁定同时存在时，锁图标优先，悬停说明、可访问名称和 TUI 同时列出两项状态。独立保护使用背景强调和状态说明区分，后续可以增加专门标记。

## 3. Explorer 内的快捷交互

### 3.1 快捷键

提供三个可配置命令：切换固定、切换独立保护、切换目录锁定。快捷键只在同用户、同会话的受支持 Explorer 位于前台时处理，不改变其他软件的输入。

默认组合在阶段 0 的按键冲突验证后确定；配置为空表示未绑定。不能注册或与已知命令冲突时给出具体原因，允许重新设置，不静默抢占已有快捷键。

按键处理要求：

1. 捕获一次按下动作，忽略长按自动重复，防止连续固定、解除固定。
2. 在目标 UI 线程重新核对前台窗口和活动标签身份，不依赖上次扫描的选中状态。
3. 只修改这次按键对应的标签；身份变化时取消并提示，不转而修改新选中的标签。
4. 在必要的关闭、导航保护入口准备成功后提交状态。
5. 确认实际状态和外观，再发送系统通知。

快捷键处理机制在阶段 0 选择。若采用进程级热键，要验证键盘布局、占用和前台过滤；若采用 Explorer 内按键处理，要验证输入焦点、地址栏和菜单行为。禁止笼统吞掉所有键盘输入。

### 3.2 系统通知

使用 Windows 系统通知，默认开启，提供“全部、仅失败、关闭”选项。操作成功示例：

- “已固定：VoiceInput”。
- “已取消固定：VoiceInput”。
- “已保护：参考资料”。
- “已锁定目录：D:\Projects\TabTail”。
- “导航已在新标签中打开，原目录保持锁定”。

通知在状态真实确认后发出。保护失败、图标失败和尚待确认分别表达，不把代理 ACK 当成保护成功。

误关拦截提示为“此标签已保护，请先取消固定或解除保护”。短时间重复误关合并提示，避免系统通知刷屏。通知不可用或用户关闭系统通知时，仍保留图标与 TUI 状态，不影响保护能力。

点击通知定位原窗口和原标签；标签已关闭或身份失效时提示已不存在，不激活复用的窗口句柄。通知注册、激活和打包方式须支持当前 Win32 CLI 安装及未安装的开发副本，不能预先假设已有应用身份。

### 3.3 TUI 与 CLI

TUI 标签列表增加紧凑状态列；详情显示固定、独立保护、有效保护、目录锁定、锁定目标、外观来源、实际应用结果和错误。列表支持按状态筛选，从详情执行定位和切换。

设置页增加“标签保护与快捷键”“标签外观”，保持简体中文 / English、Nord TUI、键盘可达及最低 72×24。Explorer 标签外观颜色不受 TUI 的 Nord 色板限制。

以下保留最初的接口规划；v0.7 的最终命令以 `--help` 和 [测试步骤](testing-tab-features.md) 为准：

```text
tabtail tabs pin <tab_id> on|off
tabtail tabs protect <tab_id> on|off
tabtail tabs lock <tab_id> on|off
tabtail tabs style <tab_id> ...
tabtail tabs style-reset <tab_id>
tabtail tabs locate <tab_id>
tabtail shortcuts show
tabtail shortcuts set <action> <chord>
```

脚本接口使用明确的 on/off，避免网络重试或重复执行 toggle 导致反向切换；本地快捷键可以使用 toggle。所有标签命令保留运行期标识与实例校验。

## 4. 防误关闭与目录锁定的行为边界

### 4.1 关闭入口

| 入口 | 目标行为 | 发布条件 |
| --- | --- | --- |
| 标签关闭按钮 | 拦截受保护标签的关闭请求 | 实测命中真正关闭入口 |
| 鼠标中键关闭 | 同上 | 不能仅隐藏按钮冒充支持 |
| Ctrl+W | 同上 | 核对实际目标标签，其他标签正常关闭 |
| 标签右键关闭 | 同上 | 独立验收菜单命令路径 |
| 关闭其他／右侧标签（系统提供时） | 跳过受保护标签，其余按用户意图关闭 | 无法保证时拒绝整次批量操作并解释 |
| 辅助功能或其他正常关闭命令 | 同一关闭决策生效 | 验证核心入口能覆盖，不能只处理鼠标 |
| 窗口关闭按钮、Alt+F4、任务栏关闭 | 含受保护标签时询问“取消关闭／明确关闭整个窗口” | 后续阶段接入，未验收前明确列为不覆盖 |
| 结束进程、崩溃、注销、系统关机 | 不承诺阻止 | 可由后续恢复记录补救，不妨碍关机 |

隐藏关闭按钮只能作为外观选项，不替代关闭请求拦截。无法覆盖约定入口时不能把该版本标为“防误关闭已完成”。

### 4.2 导航入口

验证双击文件夹、地址栏输入、面包屑、侧边栏、收藏项、前进／后退／上一级、Shell 发起的导航及程序化导航。以实际提交导航前的决策入口为主，记录请求目标和标签身份，避免转发后重新进入锁定逻辑造成递归。

导航到相同目录可直接刷新；不同目录在新标签中打开。导航失败或目标不可用时保留原位置并报告。文件重命名、目录被移动或删除、网络断开不能被解释为用户导航并无限重开标签。

锁定目标同时保存可用的 Shell 身份和规范路径。首版遇到目标身份变化标记“锁定目标需重新确认”，保留状态但不能谎报正在可靠保护；由用户解除或重新锁定当前目录。

## 5. 标签文本、背景与图标样式

### 5.1 文本

支持字体、字体颜色和是否加粗：

| 字段 | 值 | 规则 |
| --- | --- | --- |
| 字体 | 跟随系统／已安装字体名称 | 默认系统字体；不存在时回退并提示 |
| 字体颜色 | 跟随系统／`#RRGGBB` | 支持分别设置深浅主题和交互状态 |
| 加粗 | 继承／否／是 | “否”显式覆盖上层的加粗；不等于继承 |

字体必须从系统已安装字体中选择，也允许输入后校验。首版不安装、不下载、不随包附带用户字体。保留中文和其他字符的系统字体回退，不能为自定义西文字体丢失中文标题。

首版保留系统字号。改变字体或加粗后重新测量内容：随内容宽度遵守既有最小／最大值；固定宽度遵守固定值，标题过长沿用截断。图标和关闭按钮的位置、点击区域不能被字体设置破坏。

标题内容继续使用现有层级与目录规则。手动改名、目录别名和标题模板属于后续独立设计，不因设置文本样式而改变目录或标题策略。

### 5.2 标签背景色

普通、固定、独立保护和目录锁定标签均可配置背景色，状态样式可单独启停。背景仅覆盖标签本体，不覆盖整条标签栏、新建按钮、地址栏和文件列表。

每套样式区分浅色／深色主题，以及未选中、悬停、选中三种状态。选中优先于悬停，焦点指示保持清晰；关闭按钮也必须可辨认。未配置的字段继承系统或上层设置。

默认固定样式为轻度暖色背景与醒目图钉，正文跟随系统；目录锁定可使用另一套轻度强调色。具体浅深主题色值在实机验证后确定，不把一个固定的淡色背景强行用于深色主题。

自定义颜色显示对比度预览；低可读性给出提示并提供恢复。高对比度模式默认使用系统文字与背景，仅保留可辨认的状态符号。选择系统颜色时恢复原资源／绑定来源，不能只写入一个看起来接近的硬编码色值。

### 5.3 图标

本轮确认的默认方案是**直接替换图标**：固定使用图钉，目录锁定使用锁，不默认叠加到文件夹上。解除相应状态后重新计算有效图标，最终恢复当前目录的原生图标。

统一采用面性、实心、圆润风格。现有素材：

| 用途 | 文件 | 默认颜色 |
| --- | --- | --- |
| 固定标签 | [pin-rounded.svg](../assets/icons/pin-rounded.svg) | 橙色 `#F59E0B` |
| 锁定目录 | [lock-rounded.svg](../assets/icons/lock-rounded.svg) | 橙色 `#F59E0B` |
| 可选自定义文件夹底图 | [folder-teal-reference.svg](../assets/icons/folder-teal-reference.svg) | 青蓝渐变 |

图钉与锁的颜色均允许独立设置，不限 Nord。默认靠形状区分两种状态，允许用户另设不同颜色。图标的尺寸、对齐和留白保持与 Explorer 原生位置协调，按 DPI 渲染，验证 100%、150%、200% 和跨显示器移动。

原生图标包括普通文件夹、桌面、此电脑、磁盘、网络和其他特殊位置，不统一替换底层目录图标，不写 `desktop.ini`。导航期间即使显示状态图标，也持续跟踪原生图标源，以便解除后恢复最新图标，而非第一次缓存的过期图标。

首版将受控 SVG 素材打包，选择实际支持的 SVG 渲染或栅格化加载路径；不能假定 Explorer 的任意图标属性都直接接受 SVG。后续自定义图标导入先支持 PNG／ICO，SVG 导入需要明确尺寸、资源和解析限制。文件导入后复制到 TabTail 数据目录，以内部 ID 引用，不依赖下载目录里的临时文件。

保留未来的“原图标＋角标”显示模式，作为可选项另行验收；之前绘制的文件夹组合款属于备选素材。系统 Segoe 图钉可作为兼容回退，是否与 Explorer 实际资源相同须验证，不写死字体资源索引。

### 5.4 样式继承

按字段合并，优先级从高到低：

1. 当前标签的临时外观覆盖。
2. 锁定目录状态样式。
3. 固定状态样式。
4. 独立保护状态样式。
5. 首条命中的已启用目录外观规则。
6. 全局外观默认值。
7. Explorer 系统样式。

状态样式只覆盖其明确配置的字段。例如锁定只指定图标时，固定背景仍有效。图标遵循同一字段优先级，临时自定义图标覆盖状态图标时，TUI 必须提示状态将依靠背景和文字说明表达。

“恢复继承”删除当前覆盖；“使用系统值”是显式覆盖，应能阻止上层状态颜色继续生效。两者在配置和 TUI 中必须分开，不能共用一个含糊的“默认”。

目录外观匹配复用现有精确路径／正向通配符引擎，不增加正则、前置 `!` 或否定字符集。标题规则与外观规则独立匹配，避免仅调整背景色就改变现有标题规则的优先级。

## 6. 设置保存与状态反馈

设置编辑使用草稿、应用、重新载入三步，不边输入边写配置；快捷键状态切换立即执行。

- 有草稿时明确显示“尚未保存”，预览标记为预览。
- 当前运行状态与草稿分开显示，不把界面选中的模式当成已生效。
- 在文件锁内比较被编辑字段组的原始值，语言、规则、层级等无关更新不使外观草稿失效。
- 同一字段组被别处修改时保留草稿，提供重新载入；不自动重试覆盖最新设置。
- 目标值已经一致时允许幂等提交。
- 分别反馈配置已保存、策略已接收、行为保护已生效、外观已确认。
- 外观失败不撤销已经可靠生效的保护，但必须显式提示“保护已启用，外观未完成”。

### 6.1 配置草案

下例为未来 schema 3 的接口方向，字段在对应阶段实施；当前 schema 2 不能直接使用。读取旧配置采用默认值，迁移只在明确保存时执行，升级前备份；旧版不理解新 schema 时应拒绝写入。

```toml
schema_version = 3

[shortcuts]
toggle_pin = ""
toggle_protection = ""
toggle_directory_lock = ""

[notifications]
mode = "all" # all | errors | off

[tab_behavior]
pinned_tabs_protect_close = true # 首版固定为 true，未来才考虑暴露选项
locked_navigation = "new_tab" # 支持的入口转发；不能转发时阻止并提示

[tab_style.default.text]
font_family = "system"
font_color = "system"
bold = "inherit" # inherit | false | true，false / true 使用布尔值

[tab_style.pinned]
enabled = true

[tab_style.pinned.icon]
source = "builtin:pin-rounded"
color = "#F59E0B"

[tab_style.locked]
enabled = true

[tab_style.locked.icon]
source = "builtin:lock-rounded"
color = "#F59E0B"

# 未写入的状态颜色继承默认策略；system 表示显式恢复系统来源。
# 支持的背景配置位置示例：
# [tab_style.pinned.light.background]
# normal = "#FFF3D6"
# hover = "#FFE6AE"
# selected = "#FFD58A"
# 这些色值仅示例，默认值需实机验收后确定。
```

解析必须拒绝未知枚举、非法颜色、缺失图标和错误类型。行为配置、样式配置和运行期标签状态分开；不能把临时 `tab_id` 存成跨重启的目录身份。

## 7. 技术接入与状态安全

### 7.1 先验证能力，再提供入口

现有标题 Hook 与 XAML 宽度接入仅证明标题和尺寸可改，尚不能证明关闭／导航可拦截、图标可替换、全部样式状态可稳定覆盖。

能力拆分为 `pin_state`、`close_guard`、`navigation_guard`、`icon_style`、`text_style`、`background_style`、`notifications`、`window_close_guard`、`restore_session`，逐项报告支持情况和错误。缺失行为拦截时不提供看起来成功的保护开关。

固定必须先确认关闭保护能启用；外观确认失败可以保留行为保护。目录锁定必须先确认导航拦截生效，不能只显示锁图标。状态通知解释部分成功，而不是统一显示“完成”。

### 7.2 身份、事件与执行线程

复用现有用户 SID、会话、Explorer 进程创建时间、原生标签 GUID 和窗口身份校验。关闭／导航决策在目标 UI 线程执行，避免扫描延迟导致改错活动标签。标签拖动到另一窗口时，仅在确认同一标签身份后迁移状态；新 GUID 或复用 HWND 不能自动继承。

关闭和导航的同步决策使用进程内已校验策略，不在拦截入口等待磁盘、TOML、通知或远程 IPC。日志与通知放到异步队列；避免在持锁状态下调用未知 UI 或 COM 回调。

### 7.3 样式接入与恢复

优先修改已存在的图标、标题和背景控件及其资源／状态，不重建整个标签模板。记录属性原始本地值、资源来源、绑定和状态关系；不支持安全保存／恢复的属性暂不暴露。

导航、主题变化、选中／悬停、控件重建、字体变化及 DPI 变化都要重新应用有效样式。事件驱动优先，扫描负责补漏，不用频繁强写覆盖系统动画。

所有 COM／XAML 对象按所属线程使用；使用弱引用和代次标识处理控件销毁，恢复与清理幂等。图标与字体加载、SVG 渲染和颜色计算不能阻塞 UI 拦截路径。

### 7.4 进程生命周期

- 退出 TUI：代理继续，固定、保护、锁定与样式保持。
- 正常停止定制／退出代理：先移除关闭和导航限制，再恢复原生图标与外观，逐项报告结果。
- 代理异常退出：沿用有界租约思路；租约失效解除保护与锁定，并尝试恢复系统外观，避免 Explorer 永久无法操作。
- Explorer 退出：回收旧进程状态，不向复用 PID／HWND 发恢复请求。
- 未明确确认的恢复不能显示为完成；进程已退出可以单独判定无需恢复。
- DLL 是否可热更新、是否需退出 Explorer，以实际加载机制为准；不自动重启 Explorer。

## 8. 分阶段实施与验收

### 阶段 0：Explorer 能力验证

目标：建立可复核证据，确定支持边界和快捷键方案。

交付：活动标签可靠识别；关闭／导航入口探针；图标、字体、文字颜色、加粗、背景三态的设置与恢复探针；通知原型；按能力报告支持情况。

验收：已有多个标签、同路径双标签、特殊目录、深浅主题、常见 DPI；真实读取与视觉检查结合。实际关闭仅使用专门测试标签；不自动关闭用户工作窗口。未经覆盖验证不进入相应功能交付。

### 阶段 1：固定标签与单标签防误关闭

目标：解决最常见的误关闭问题。

交付：固定与独立保护状态、前台活动标签快捷键、圆润实心图钉替换、成功／失败系统通知、TUI 状态与手动开关、计划 CLI 的对应子集。

验收：关闭按钮、中键、Ctrl+W、右键关闭及系统存在的批量关闭入口；未保护标签不受影响；取消固定不移除独立保护；同路径双标签互不影响；长按不反复切换；状态失败不发成功通知；正常停止与租约到期可解除。整窗关闭边界必须明确显示。

### 阶段 2：锁定目录

目标：保持工作位置，同时允许在新标签浏览其他目录。

交付：锁定／解除锁定快捷键、目标身份记录、导航拦截与支持入口的新标签转发、圆润实心锁替换、双状态说明和通知。

验收：地址栏、双击、面包屑、侧边栏、前进／后退／上一级、Shell 导航逐项通过；同目录刷新不受阻；一次导航只新开一个标签；无法转发时可靠阻止；目标移动／删除、网络断开、控件重建不死循环；固定与锁定能独立切换。

### 阶段 3：完整标签外观与规则

目标：让固定、保护、锁定标签容易区分，并支持个人字体偏好。

交付：全局、目录、状态和临时标签外观；字体选择、文字颜色、加粗；深浅主题下标签背景三态；独立图标颜色；恢复系统与恢复继承；样式预览和分组并发保存。

验收：三态和主题切换后仍能区分活动标签；中文回退正常；加粗 false 可覆盖 true；原生图标在导航后解除能正确恢复；固定／自适应宽度重新测量；无效字体与素材有反馈；72×24 中英文流程可完成；无关配置更新不使草稿失效，真实冲突不丢草稿。视觉成功同时检查图标、文字和背景，不仅检查属性写入。

### 阶段 4：整窗关闭与恢复工作标签

目标：补齐窗口级丢失和重启后的工作恢复。

交付：含保护标签的窗口关闭提示；固定目录清单；用户主动保存／恢复；TUI 批量管理。登录或重启后自动恢复作为单独可选设置，默认关闭。

验收：窗口关闭按钮、Alt+F4、任务栏关闭分别验证；明确关闭后不立刻重开；恢复去重与跨窗口映射有确定规则；无效目录、离线网络和大批标签有数量限制；只保证重新打开目录，不承诺恢复滚动位置、选中文件或历史栈。自动恢复不阻止系统关机。

### 后续候选

固定标签左置、快捷键循环跳转固定标签、状态角标叠加、自定义图标导入、目录别名和标签组，分别按使用价值与适配成本决定，不阻塞前四阶段。

## 9. 验证与发布记录要求

每阶段保留支持的系统文件版本、行为覆盖矩阵、真实控件读回、失败路径、恢复结果及人工视觉证据。记录测试用标签与用户工作标签的边界，避免把 ACK、配置保存或图标改变当作功能保护的证据。

自动测试重点覆盖状态组合、幂等请求、同路径多实例、身份复用、关闭／导航决策、配置继承与冲突、失联租约、资源释放和回退。人工验收覆盖真实输入入口、通知、拖动、主题、缩放、输入法与辅助功能。

阶段完成后更新 [实现状态](implementation.md)、CLI 帮助和对应真机测试步骤；未完成的能力继续标明待验证。现有目录标题策略与宽度功能保持独立验收，新增功能失败不能连带破坏原有行为。
