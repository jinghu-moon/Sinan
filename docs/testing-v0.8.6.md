# 0.8.6：目录规则表单重设计

本次重新设计目录规则弹窗，并增加可复用的 `form_input_options` 输入框样式。页面顶部的搜索框和其他编辑器保留原有布局。

## 界面与行为

- 输入框有常驻圆角边框、Nord 深灰背景及左右留白。聚焦时边框青色，悬停时蓝色，深度非法时红色。文本内容不随聚焦整行反白；标签与占位提示分离。
- 名称、测试目录、层级为单行框；路径／模式为三行文本区域。保留原生输入组件的中文编辑、鼠标定位、横向／纵向光标滚动和多行换行行为。边框和留白在输入组件自身变换中绘制，点击区域与光标位置一致。
- 弹窗按匹配范围、显示方式、实时预览分组。至少 110 列时使用左右两栏；较窄时纵向排列，预览精简并放在测试目录上方。Tab 切换焦点时表单区域跟随滚动。
- 底部“应用设置／取消操作”固定显示。输入或检验错误保留草稿及弹窗；应用前仍执行原有规则验证。
- 预览是尚未提交的草稿，显示计算标题、来源与影响数量。命中当前草稿时显示规则名称，避免只出现自动生成的规则 ID。
- 每次打开默认聚焦名称。F7 切换语言保持草稿；Esc 取消。弹窗外的背景使用低亮度显示。保留此前四字中文操作按钮及输入线程隔离修复。

## 真机步骤

```powershell
Set-Location 'D:\100_Projects\110_Daily\test2'
$tt = (Resolve-Path '.\build\package-v0.8.6\bin\tabtail.exe').Path
$data = Join-Path $PWD 'build\manual-v086-data'
& $tt --data-dir $data tui --lang zh-CN
```

1. F3 → 新增规则，或 F2 选中标签 → 创建规则。默认焦点应在名称，边框青色；其他输入框边界仍可见。
2. 中文输入名称，使用左右键、Home／End、退格；鼠标点击文本或框内留白后继续编辑，光标位置应正常。
3. 路径区域输入多条模式，Enter 换行。切换通配模式／精确目录，检查提示和实时预览；输入长路径，移动到末尾确认内部滚动。
4. 层级改为 3，预览实时变化。改为 0 或非数字，边框与验证结果提示错误；点击应用仍留在弹窗。改回有效值后继续。
5. 依次切到 110×36 和 72×24。宽版分列；窄版 Tab 到测试目录时仍能看见计算标题，底部应用和取消按钮始终可见。
6. F7 切换英文，检查标签、提示及选项翻译；编辑草稿不得丢失。Esc 取消后重新打开，焦点应回到名称。

仅检查表单无需启用标题定制或重启 Explorer。新测试目录使用独立配置；保留原配置和原路径升级的方式见 [0.8.4](testing-v0.8.4.md)。

## 自动验证

```powershell
cmake --build build/msvc-lifecycle --config Release --parallel 6
ctest --test-dir build/msvc-lifecycle -C Release --output-on-failure
```

组件测试检查真实输入框的圆角与焦点／错误边框、内部背景与留白、占位色、中文输入和删除、Tab 导航、鼠标点击、多行编辑；规则弹窗覆盖中英文宽窄布局、固定底栏、默认焦点、窄窗口中的预览可见性和非法深度保留草稿。

`build/msvc-lifecycle/tui-artifacts/zh-CN-rule-editor.cells.json` 等为实际组件单元格产物，可用 `tools/render-tui-snapshot.py` 生成预览。Windows Terminal 的字体、DPI、输入法候选窗口和鼠标手感仍需真机验收。
