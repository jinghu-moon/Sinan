# 09 资源管理器显示文件夹大小

## 首版实现进度

「常规 → 资源管理器交互」已接入 TDesign 设置。启用后，代理按需启动 `sinan-folder-sizes.exe`，使用固定版本的 Everything SDK3 查询。独立的 `sinan-folder-view.dll` 读取有界的共享缓存，通过模块哈希、已加载映像标识和入口指令校验确认兼容性。当前验证目标为 Windows 11 24H2 x64 的 `ExplorerFrame.dll 10.0.26100.1441` 和 `windows.storage.dll 10.0.26100.8875`。

首版通过 Shell 条目更新和可见目录的周期复查完成刷新。使用 Everything 1.5.0.1416b 实测，复制进当前标签的文件夹自动显示大小，文件内容变化后单元格随之更新。本次复制样例约 323 ms 显示，性能分位数仍待测量。

已通过独立 Shell 测试验证按原始字节比较。大小排序入口已被其他扩展接管时，司南保留该扩展的排序，文件夹大小及自定义格式继续生效。排序中的自动重排及选择、焦点和滚动位置需继续做真机验收。

Everything 1.5.0.1416b 真机验证通过索引日志触发深层修改与跨目录移动后的重查。资源管理器「大小」列的悬停提示已验证精确字节数、空文件夹的 `0` 字节、查询时间和索引状态。

## 使用体验

在司南「常规 → 资源管理器交互」打开「显示文件夹大小」。资源管理器切换到「详细信息」视图后，原有「大小」列会显示文件夹及其子目录在 Everything 索引中的逻辑字节总数。该数值适用于估算目录内容大小，磁盘分配、压缩、硬链接和索引排除项等因素会让它与「占用空间」有所不同。

| 操作或状态 | 资源管理器中的表现 |
| --- | --- |
| 打开目录或滚动到新位置 | 文件夹大小按需补齐，优先处理可见行。 |
| 把文件夹复制或移动到当前标签 | 新行出现后立即提交查询。Everything 返回首个有效结果时自动填入，复制过程中随索引变化刷新，复制完成后自动收敛到最终值。 |
| 修改文件夹中的文件，或在其中添加、删除内容 | 更新受影响的文件夹大小，包括多层子目录里的变化。 |
| 切换单位或小数位数 | 使用已有字节值重新格式化当前可见行。 |
| 点击「大小」列标题 | 在 Explorer 的现有分组内按原始字节数排序。空目录按实际的 `0` 排序。复制期间大小可持续更新，行位置按批次调整。 |
| 索引结果为 `0` | 按当前单位显示零值。 |
| 正等待索引、当前路径未被索引，或查询不可用 | 大小单元格留空。依赖问题集中显示在司南设置页。 |

首期适配 Windows 11 x64 上通过验证的资源管理器构建，覆盖已索引的本地 NTFS 普通文件夹。虚拟位置、搜索结果、网络共享、重解析点和区分大小写目录随适配验证逐步扩展。功能默认关闭，旧配置按默认值读取。

## 界面入口与扩展

首版在司南现有「常规 → 资源管理器交互」设置开关、单位和小数位数。资源管理器原有「大小」列负责显示、排序和实时刷新。关闭 WebView2 设置窗口后，司南代理继续为资源管理器提供大小查询和更新。

在前台资源管理器的「详细信息」视图中，将鼠标停在文件夹的「大小」单元格约半秒。提示显示精确字节数、最近成功查询的本地时间和索引状态。未知大小及尚无成功查询的时间显示为 `—`，空文件夹显示 `0` 字节。索引状态区分已索引、等待查询、暂无索引结果、索引加载中、Everything 未连接和版本不兼容。通过 UI Automation 的 `System.Size` 标识确认列，并从当前 Shell 视图读取对应项目。

| 扩展顺序 | 功能 | 入口与交互 |
| --- | --- | --- |
| 1 | 选中项统计 | 选中文件或文件夹时，资源管理器底部状态栏自动更新选中项字段。 |
| 2 | 查看最大子项 | 从文件夹右键菜单按需打开司南 WebView2 面板。用 Vue 与 TDesign 表格列出按大小排序的直属文件和子文件夹，双击子文件夹下钻，使用面包屑返回上级。关闭面板后释放其 WebView2 实例。 |
| 3 | 目录体积阈值 | 在现有设置页给指定目录配置上限，超过后在资源管理器大小单元格旁标记。仅用已知字节值判断，标记入口随 Explorer 构建验证。 |
| 4 | 磁盘占用详情 | 在按需打开的详情中并列展示逻辑大小与磁盘实际占用。先验证压缩、稀疏文件和硬链接的统计口径。 |

## 单位与小数

「常规 → 资源管理器交互 → 选中项统计」可分别勾选文件数量、文件夹数量和大小，默认显示三项。取消勾选全部选项可恢复系统显示。数量只统计直接选中的项目，选中的文件夹大小包含 Everything 已索引的后代。文件大小读取系统文件属性。混选时两者相加，遇到未知大小时显示已知小计和未知项数量。统计沿用此处的单位和小数位设置，可独立于大小列开关使用。状态栏适配仅在已验证的 Windows 11 资源管理器版本上生效。

| 单位模式 | 规则 | `1,572,864` 字节，保留 2 位小数 |
| --- | --- | --- |
| 智能单位 | 根据字节数选取量级。默认使用 IEC 的 `B、KiB、MiB、GiB、TiB、PiB、EiB`，也可选择 SI 的 `B、kB、MB、GB、TB、PB、EB`。 | `1.50 MiB` 或 `1.57 MB` |
| 固定单位 | 所有文件夹统一换算为用户选定的内置单位。 | 固定 `GiB` 时为 `<0.01 GiB` |
| 自定义单位 | 设置显示名称和每单位对应的正整数字节数。 | 名称为 `块`、每块 `4096` 字节时为 `384.00 块` |

- 小数位数可选 `0–6`，默认 `2`。保留用户指定的尾随零。内置 `B` 直接显示整数字节，例如 `0 B`。使用 Windows 区域设置的小数分隔符。
- 正数四舍五入。智能模式下，舍入结果达到下一单位的进位阈值时，按下一单位重新计算。固定和自定义模式下，极小的非零值以 `<` 加最小显示刻度呈现，便于与零值区分。
- 自定义名称去掉首尾空白后须为 1–12 个 Unicode 字符，控制字符和换行视为无效。每单位字节数允许 `1–10^18`。GUI 用十进制文本传递除数，原生层解析并校验，避免 JavaScript 数字精度丢失。
- 格式化使用整数商、余数和足够宽的中间计算，覆盖 64 位字节值及舍入进位。Explorer 的 `System.Size` 属性仍承载 `VT_UI8` 字节值，显示文本只在已识别的文件夹大小单元格上生成。

设置页复用现有 `SettingSwitch`，单位模式与单位选项用 TDesign `Select`，自定义名称、除数和小数位数用 TDesign `Form`、`Input` 和 `InputNumber`。提供一行格式预览。复用 `vue-sonner` 反馈保存结果，Everything 连接状态和配置说明显示在设置项下方。

配置建议放在 `sinan.toml`。单位选项由司南统一校验，GUI、CLI 和代理通过现有应用接口读写。

```toml
[folder_sizes]
enabled = false
unit_mode = "auto"     # auto | fixed | custom
unit_system = "iec"    # iec | si
decimal_places = 2
# fixed_unit = "GiB"
# custom_unit_label = "块"
# custom_unit_bytes = 4096
# everything_instance = "工作"
```

## 引入 Everything SDK

**首期使用官方 Everything SDK3。** 依赖版本固定为 `3.0.1.12`，归档 SHA-256 为 `d35ed05f339d82b9e7add43fda82efc497ee5b09818b8fe0152fd90737b614fc`。构建沿用 CMake 的版本与哈希校验，使用官方 `include/Everything3.h` 和 `src/Everything3.c` 构建静态库。Windows x64 包内只由按需启动的目录大小查询进程链接 SDK。发布包随附 MIT 许可证并登记 `THIRD_PARTY.md`。Everything 完整版由用户安装并在当前桌面会话运行，在「工具 → 选项 → 索引」启用「索引文件大小」和「索引文件夹大小」。[SDK 发布与 API](https://www.voidtools.com/forum/viewtopic.php?t=15853) · [官方归档](https://www.voidtools.com/Everything-SDK-3.0.1.12.zip) · [SDK 许可证](https://github.com/voidtools/everything_sdk3/blob/master/LICENSE) · [Everything 索引选项](https://www.voidtools.com/support/everything/options/)

1. `Everything3_ConnectW(nullptr)` 先探测默认实例，再尝试 `Everything3_ConnectW(L"1.5a")`。用户指定实例时只连接该实例。复用会话内连接，Everything 退出或重启后按退避策略重建。正常关闭时调用 `Everything3_DestroyClient`。
2. 用版本 API 和 `Everything3_IsDBLoaded` 判断客户端与索引是否可用。参考实现从 Everything `1.5.0.1384a` 起使用直查接口，实际发布的最低版本由当前 SDK 与 Everything 的实测矩阵确定。Lite 版和只有 Windows 服务运行的情况提示启动支持 SDK 的 Everything 桌面客户端。
3. 传入文件夹的 Unicode 完整路径，调用 `Everything3_GetFolderSizeFromFilenameW`。返回 `UINT64_MAX` 时读取 `Everything3_GetLastError` 诊断并将结果标为未知。该哨兵也可能代表未索引或大小索引关闭，单条查询失败不足以判断全局索引设置。返回 `0` 时保留为已知大小。保留路径的实际大小写，根据已验证的 SDK 路径规则处理长路径，复用现有路径校验时保留原始路径供 SDK 查询。
4. 现有 `src/platform/everything.cpp` 使用 Everything SDK 的 `Query2W` 消息读取搜索结果路径。后续如需支持 Everything 1.4，可在同一提供者接口下扩展该通道，请求 `FULL_PATH_AND_FILE_NAME | SIZE`，按完整路径和文件夹类型校验结果，区分已知 `0` 与缺失值。验证索引配置、实例及实时刷新表现后再准入 1.4。[现有 Everything 搜索](../src/platform/everything.cpp) · [旧版 SDK 的大小查询](https://www.voidtools.com/support/everything/sdk/everything_getresultsize/)

## Explorer 接入与后台查询

参考 Windhawk 的属性读取路径。`windows.storage.dll` 中的 `CFSFolder::_GetSize` 提供文件系统条目的大小。某些详细信息视图先从 `CDefCollection` 缓存或 `WIN32_FIND_DATA` 取值，文件夹缓存缺失时可能需要走正式属性提取。`CFSFolder::CompareIDs` 是大小排序的候选适配入口。参考实现的全局单位格式化和同步查询适用于其自身的接入方式。司南围绕详细信息视图中的文件夹行实现属性、格式化与更新三个入口，使用已有符号准入框架独立实现。参考模组的源码为 GPLv3。[参考模组](https://windhawk.net/mods/explorer-details-better-file-sizes) · [司南符号兼容方案](05-symbol-compatibility.md)

```mermaid
flowchart LR
    View[Explorer 详细信息视图] --> Cache[视图的内存快照]
    Events[标签与目录变化] --> Agent[sinan-agent]
    Cache -. 缺失项异步入队 .-> Agent
    Agent --> Worker[目录大小查询进程]
    Worker --> SDK[Everything SDK3]
    SDK --> Worker --> Agent
    Agent -->|发布新快照并通知受影响行| Cache
```

- **Explorer 适配层**在验证过的文件系统详细信息视图内识别文件夹行。以视图代际、父目录和条目标识关联数据。属性回调先保留原生返回值，仅在目标文件夹属性为空且缓存命中时补入 `VT_UI8`。缓存未命中时将条目标识投入有界队列，在视图所属线程的后续任务中提取路径，再由后台通道送交代理。属性和排序回调的调用链保持内存读写，文件系统访问、跨进程等待和 SDK 调用交给后台。格式化入口需要同时确认视图、项目类型及 `PKEY_Size`。
- **司南代理**复用标签观察与本地 IPC 的 SID、会话、对端身份校验。按路径合并多标签请求，把新出现和可见的行排在队首。使用有上限的缓存和队列。优先淘汰过期和非活动数据。每条响应携带视图代际、路径版本及 Everything 连接代际，只有三者匹配才进入当前视图。切标签、改名、删除、断线和禁用功能时撤销相应请求或快照。[标签观察](../src/agent/tab_tracker.cpp) · [本地 IPC](../src/ipc/pipe.cpp)
- **查询进程**由代理在相同用户和会话下按需启动，串行持有 SDK 客户端。代理对连接、查询请求设外部期限，超时后回收查询进程，避免 SDK 的同步连接或读取阻塞代理。可见查询的初始设计预算为单批 1 秒，超时后采用 `1、2、5` 秒退避并限制重启频率。禁用功能时结束查询进程并清空订阅。空闲无活动视图时暂停查询，连接和进程可按空闲期限释放。
- **排序**首先验证原生排序是否读取补齐的数值。按大小排序时，优先查询可见行，再分批查询视图中其余已枚举的文件夹，以便排序覆盖整个列表。如果需要适配 `CompareIDs`，用已验证的列映射只处理 `PKEY_Size`，在一次排序中使用同一份视图快照，按已知状态、字节数、名称及原生条目顺序形成稳定比较关系。升序时已知值在前，降序遵循 Explorer 的方向规则。大小文本随缓存更新，影响排序的变化合并后再重排。复制期间验证选中项目、焦点与滚动位置稳定。其他列及分组使用 Explorer 的规则。
- **兼容性准入**验证 `windows.storage.dll` 及相关视图模块的匹配 PDB、精确符号、函数边界和调用契约。逐构建确认属性提取、单元格格式化、刷新和排序的真实调用路径。若只有数值路径通过，可在诊断中提供原生单位模式。关键属性或刷新路径无法验证时恢复原生显示，并在司南中报告构建不受支持。

## 实时刷新

1. **先刷新用户刚操作的行。** 订阅活动文件系统标签的目录变更。Explorer 添加复制或移动后的行时立即安排查询。重命名或删除时撤销旧路径缓存，目标项以新路径单独查询。对同一行连续到来的写入事件进行约 `100–200 ms` 合并，首次查询及时派发，后续更新按批次提交。
2. **追踪子目录变化。** 查询进程通过独立 SDK3 连接调用 `Everything3_GetJournalInfo` 和 `Everything3_ReadJournalW`。代理从有界队列读取新旧路径，并按路径组件匹配受影响的文件夹。断线重连时尝试从原游标续读。日志重建、游标失效或队列溢出时重查可见目录。日志关闭或无法读取时约每 `0.65–3` 秒复查可见条目。日志监听正常时，已知大小约每 `30` 秒复核一次，日志命中项优先查询。切回隐藏标签时重新核对可见行。`agent status` 的 `folder_sizes.journal` 和 `folder_sizes.journal_rechecks` 分别报告监听状态和日志触发的重查条目数。[SDK3 API 与版本变更](https://www.voidtools.com/forum/viewtopic.php?t=15853) · [Everything 索引日志](https://www.voidtools.com/support/everything/index_journal/)
3. **处理复制与索引的时间差。** Explorer 新行可能早于 Everything 索引。若第一次查询未知，或复制期间索引值仍可能变化，初始以 `150、300、600 ms` 复核，再退到约 `1–2 s`，限于近期受影响的可见项。一次结果可能是复制中途的有效大小，后续以更新的索引值覆盖。连接或索引重建时，清除旧代际结果并重新提交当前可见项。
4. **把缓存更新带到视图。** 结果提交后，在该视图所属线程合并受影响条目的刷新。原型先验证条目更新通知能否使大小属性重新提取并重绘，例如使用 `SHChangeNotify(SHCNE_UPDATEITEM, SHCNF_IDLIST, …)` 配合视图缓存的失效行为。优先用定向视图刷新。若使用 Shell 广播，通知订阅侧须验证不会把自身刷新当成新一轮目录改动。常态以条目为刷新单位，保持标签位置、现有选择、滚动和焦点。设置变更触发可见行文本更新，已有字节缓存继续使用。[SHChangeNotify](https://learn.microsoft.com/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify)

### 复制到当前标签的验收

在已索引的本地 NTFS 目录中打开「详细信息」视图。把一个含多层子目录的文件夹复制到当前标签，并让新行留在可见区域。记录新行出现、Everything 首次返回有效值、单元格首次绘制、复制完成、Everything 首次可查询到最终值和单元格完成更新的时间。单元格应自动出现并更新，无需 F5 或切换标签。用户连续复制、覆盖或修改同一文件夹时，迟到结果应被代际校验丢弃。

初始目标是在空闲索引和本地测试磁盘上，新行出现后 `200 ms` 内派发首次查询，Everything 索引可返回最终值后 `500 ms` 内完成绘制（P95，活动视图、可见行、正常通知路径）。索引积压和通知遗漏分别计量。周期复核路径以自动收敛验收，耗时单独记录。上述数字是原型验收目标，仍需真机测量。
