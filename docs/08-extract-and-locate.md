# 08 解压并定位实施方案

## 1. 使用方式

用户在资源管理器选中一个压缩包，或选中同一组分卷中的一个或多个文件，按下「解压并定位」快捷键。司南按配置选择工具，在后台解压到压缩包所在目录。结果准备好后自动定位，并通过 Windows 系统通知反馈。

- F6「实用工具」提供「解压设置」和「解压任务」。用户可以配置工具、查看或取消耗时任务、重新打开已有结果。
- F8「快捷键」提供「解压定位」绑定，作用域为资源管理器前台。CLI 动作拟用 `explorer.extract_archive`，快捷键配置键拟用 `extract_archive`。
- 解压工具通过命令行静默运行。工具可提供可靠进度时，「解压任务」显示百分比，其余情况显示「正在解压」。
- 首期每次触发处理一个独立压缩包或一组分卷。混选多组时提示选择一组。

## 2. 工具配置与选择

用户添加受支持的工具，填写类型、显示名和可执行文件的绝对路径。每个工具只配置一次，可以设为默认，也可以绑定到一个或多个格式。便携版使用同一套配置。初始配置留空，用户可以按需设置默认工具和格式规则。

| 设置示例 | 工具 |
| --- | --- |
| 默认工具 | 7-Zip |
| `.rar` | WinRAR 命令行组件 |
| `.tar.gz` | Windows `tar.exe` |

1. 格式键忽略大小写，优先匹配完整后缀，例如 `.tar.gz` 优先于 `.gz`。分卷先识别，再按所属格式查找工具。
2. 有专属规则时使用指定工具，无专属规则时使用默认工具。未设置工具、指定路径失效或当前格式不受支持时，提示相应设置项。
3. 首批适配候选是 7-Zip、WinRAR 命令行组件和 Windows `tar.exe`。各工具适配器负责归档检查、解压参数、非交互运行和退出结果判断。设置页展示经测试确认的普通格式和分卷方式。
4. 在 `sinan.toml` 中保存工具列表、默认工具 ID、格式映射和「完成后移入回收站」开关。复用现有 toml++ 解析和配置写入。现有配置升级后自动补齐空规则，回收开关关闭。

## 3. 分卷

选择任意一卷时，司南在同一目录识别同组候选，找到解压入口。选择同组多卷或重复触发时，只建立一个任务。下表列出计划覆盖的命名，实际支持范围按工具和格式分别验证。

| 分卷示例 | 传给解压工具的入口 | 匹配工具规则 |
| --- | --- | --- |
| `资料.part01.rar`、`资料.part02.rar` | 编号为 1 的卷，支持 `part1`、`part01`、`part001` | `.rar` |
| `资料.rar`、`资料.r00`、`资料.r01` | `资料.rar` | `.rar` |
| `资料.7z.001`、`资料.7z.002` | `资料.7z.001` | `.7z` |
| `资料.zip.001`、`资料.zip.002` | `资料.zip.001` | `.zip` |
| `资料.z01`、`资料.z02`、`资料.zip` | `资料.zip`，交给支持这种分卷方式的工具 | `.zip` |

- 文件名用于查找候选，工具或归档元数据用于确认格式、分卷关系和完整性。普通 `.001` 文件需要明确的归档依据才纳入处理。
- 入口缺失、编号断档或同一编号有多个候选时，提示可确定的具体问题。尾卷可能要等工具读取后才能确认是否缺失。发现缺卷或校验失败时保留所有源文件，提示补齐后重试。
- 用 `资料` 作为该组的包名。解压后需要新增外层目录时，目录名省去 `.part01`、`.001` 等分卷标记。
- 工具映射按基础格式生效，实际选择的工具须支持该种分卷。例如 `.zip` 的工具支持普通 ZIP 时，仍需验证它能处理 `.z01` 分卷。 [WinRAR 分卷说明](https://www.win-rar.com/split-files-archive.html) · [旧式 RAR 命名](https://documentation.help/WinRAR/HELPArcVolumes.htm) · [WinZip 分卷格式](https://kb.winzip.com/en/130395) · [7-Zip 分卷参数](https://7-zip.opensource.jp/chm/cmdline/switches/volume.htm)

## 4. 后台解压与定位

1. **捕获选中项。** 复用 Explorer 标签验证和 `selected_paths`，记录来源窗口、标签、所选绝对路径及文件身份。通过归档入口或已确认的分卷组识别重复任务。
2. **启动后台任务。** 代理快速受理，工作线程以桌面用户身份直接启动配置中的可执行文件，传入独立参数并隐藏控制台，采集退出码和有界诊断输出。用户取消时结束对应进程组，等待退出后处理临时文件。
3. **解压到同卷临时目录。** 在写入前通过经过验证的工具能力或归档检查确保输出路径留在临时目录内，拒绝无法安全处理的路径和重解析点。根据工具的退出状态及完整性检查确认结果。遇到缺卷、需要密码、校验失败、取消、空间不足或部分解压时，保留原包，清理临时结果并报告原因。
4. **发布完整结果。** 按下表决定输出目录。重名时依次使用 `名称 (2)`、`名称 (3)`。使用不覆盖的同卷重命名，处理其他进程同时创建同名目录的情况。后续定位和回收以实际发布状态为准。
5. **定位。** 从最终目录向下查找。只有一个普通子目录时继续进入，只有一个文件时打开当前目录并选中文件，遇到多项或空目录就停在当前层。保留包内的目录结构。
6. **通知。** 用户仍在来源窗口时，优先复用已打开的目标标签，可用时在来源窗口新建标签。切到其他窗口、来源窗口关闭或自动定位失败时，通过系统通知和「解压任务」提供「打开结果」。选中文件前验证目标标签的目录。通知遵循司南通知设置，并分别说明定位和回收结果。

| 顶层结构 | 输出及定位 |
| --- | --- |
| 只有一个文件夹 `项目资料\` | 沿用这个文件夹名，放到压缩包旁边，再应用递归定位 |
| `项目资料\文档\说明.pdf`，每层只有一项 | 输出 `项目资料\`，直接进入 `文档\` 并选中 `说明.pdf` |
| 单目录链的末端是空目录 | 定位到最深的空目录 |
| 两个或更多文件、文件夹 | 用包名创建外层目录，打开该目录 |
| 顶层只有一个文件 | 用包名创建外层目录，打开并选中该文件 |
| 整包为空 | 提示「压缩包为空」，保留源包 |

## 5. 解压后回收源压缩包

「完成后移入回收站」默认关闭。开启后，源包回收的条件是**完整解压且结果已发布**。标签定位失败时，已发布的文件可从「解压任务」重新打开。

- 普通压缩包只回收本次处理的源文件。分卷只回收经工具或归档元数据确认参与本次完整解压的整组文件。无法确认完整成员清单时整组保留。
- 回收前再次核对原文件身份和状态。文件被替换或改动、卷组发生变化、解压失败及发布失败时保留源文件。
- 使用 Windows 回收站，验证本地卷及网络位置上是否可回收。无法保证回收时保持源文件原位，并提示「已解压，原压缩包已保留」。禁止回收失败后改用永久删除。
- 逐个记录分卷的回收结果。回收发生部分失败时，保留解压结果并列出已回收和仍在原目录的卷。 [Windows 文件操作标志](https://learn.microsoft.com/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags) · [逐项删除结果回调](https://learn.microsoft.com/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-postdeleteitem)

## 6. 实施顺序

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 配置与动作 | 增加工具配置、格式匹配、CLI 动作、F6 设置、F8 快捷键和中英文文本 | 旧配置可加载。新配置可往返保存。可从真实入口验证默认工具和格式覆盖 |
| 2. 单包解压 | 验证工具接口。接入后台任务、取消、发布、递归定位和通知 | 可从 Explorer 触发，正确处理不同目录结构，并在切走时保留焦点 |
| 3. 分卷 | 实现入口识别、同组去重和完整性检查，建立工具与分卷方式测试矩阵 | 选首卷、中间卷或多个卷只产生一次解压。缺卷时保留源文件和已有目录 |
| 4. 可选回收 | 接入回收站和逐项结果，补齐升级前后的真实 Explorer 验收 | 默认保留源包。开启后可恢复已回收的包。不可回收或分卷成员不明时保留源文件 |

- 复用现有配置、动作目录、快捷键和 Explorer 选中项读取。归档识别、工具调用和结果处理放入可独立测试的基础模块。 [配置](../src/config/config.cpp) · [动作目录](../src/app/actions.cpp) · [Shell 选中项](../src/platform/shell_actions.cpp)
- 复用代理的路径打开、标签定位和 `reveal_file`，扩展系统通知点击处理以打开任务结果。TUI 与 CLI 读取同一个任务状态，分别显示解压发布、定位和源包回收是否完成。 [代理](../src/agent/runtime.cpp) · [通知宿主](../src/agent/interaction.cpp)

## 7. 测试与验收

开发前保存 Release 构建及配置解析、CLI、快捷键、标签定位和通知的测试基线。开发后用同一组测试回归，补充功能测试和真实资源管理器操作。

| 场景 | 验收结果 |
| --- | --- |
| 配置升级与匹配 | 旧配置加载后回收关闭。默认工具、专属规则、大小写和复合后缀匹配正确。工具移动或能力不匹配时显示原因 |
| 目录结构 | 单文件夹、多项、单文件、连续单子目录以及空目录均按规则输出和定位 |
| 并发与取消 | 同一组重复触发只建立一个任务。不同压缩包输出同名时各自发布。取消可结束工具并清理临时目录 |
| 分卷 | 每种命名覆盖选中间卷、同时选多卷、缺首卷、缺中间卷、缺尾卷、损坏与混入同名前缀文件 |
| 路径与故障 | 验证中文、空格、长路径和重名。异常归档路径无法写到临时目录外。损坏、工具警告或空间不足时不发布结果，保留源包 |
| 标签与通知 | 复用已有标签、在来源窗口新开标签、选中单文件、切走时保留焦点，从通知或任务列表重新定位 |
| 回收与恢复 | 普通包和确认完整的分卷可恢复。模拟源包替换、成员不明、回收失败、回收站不可用以及定位失败 |
