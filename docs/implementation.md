# TabTail 实现状态

## 0.11.0 行为与外观符号适配

在 0.10.0 的标题／枚举基础上新增 14 个 frame 符号、2 个 FileExplorerExtensions 符号及 3 个 Windows.UI.FileExplorer 符号。关闭保护、目录锁定、标签选择、新建、frame 重排、XAML 身份和扩展重排分别准入。actions 接口、active GUID、浏览器接口、重排服务字段、ViewModel getter slot、标签 GUID 字段通过有界指令和 vtable 引用校验推导。目录锁定通过浏览器接口取得对象，移除旧的固定浏览器字段偏移读取。

原生行为、外观和宽度桥接不再统一依赖单一 ExplorerFrame 哈希。运行期继续验证加载模块的 PE／PDB 身份、实际接口和入口；外观及重排仍要求真实读回。能力只允许在同一模块、原有 RVA／字段及已通过能力不变时增补，避免准备新缓存后必须更换已准入的地址。

三个本机 PDB 的所有 29 个目标符号及相关契约已通过只读验证；20 组 CTest、63 项本机兼容检查及 1747 项 TUI 组件检查全部通过；详见 [0.11.0 测试步骤](testing-v0.11.0.md) 和 [证据](evidence/06-native-xaml-compatibility.json)。其他系统构建与 UI 操作仍需真机矩阵，历史版本的精确构建限制描述以新版兼容设计为准。

## v0.7.1 原生标签图标修正

- 用户真机截图证明 0.7.0 改变的是任务栏预览的窗口图标，标签仍显示文件夹。此前 `WM_GETICON` 位图读回通过只覆盖窗口，不构成标签替换证据；这一结论已纠正。
- 移除 `CBrowserHost::SetIcon` Hook 和原生窗口图标写入。保护／锁定的内部入口保持独立，图标改由 XAML `TabViewItem.IconSource` 替换为 `PathIconSource`，几何来自已批准的图钉／锁 SVG。
- 从目标标签根对象实时遍历 `VisualTreeHelper`，确认实际 `PathIcon` 的几何身份、颜色与非零尺寸；诊断回调缓存遗漏新控件时不再误判。原图标按实例保留，导航更新后保存最新原值，显式 system／解除状态／停止／租约到期恢复并读回原对象。
- XAML 首次初始化的 `E_PENDING` 返回结构化待确认，代理有界重试 1.2 秒；初始化未完成使用信息通知，真正失败才告警。外观成功只认实际标签图标，不认窗口图标。恢复失败时不能把单独的原生行为恢复当作标签图标恢复成功。
- 14 组 CTest 及独立原生探针通过。覆盖图钉、锁、系统图标恢复、停止与失联恢复、任务栏窗口图标不变；用户已提供原生标签图钉截图。新证据见 [02-tab-icon-fix.json](evidence/02-tab-icon-fix.json)，参考项目调研见 [ShellTabs 标签图标实现](research/02-shelltabs-tab-icons.md)。完整主题、DPI、鼠标／菜单输入与通知验收仍按测试文档继续。
- 新分发目录与旧版分开，不覆盖用户正在运行的 0.7.0。更新仍需先停止旧代理并由用户保存工作、退出占用旧 DLL 的 Explorer。

工作恢复默认最多 20 项（可配 1..100）、20 秒总预算、单次网络检查 800ms、最多 4 个后台检查。保存组映射到按 HWND 排序的现有窗口，数量不足时循环；没有窗口时创建一个锚窗口。复用目录时仅增加保存的状态，不解除用户已有保护；不恢复历史栈、滚动位置或文件选择。自动恢复默认关闭；用户启用后通过相邻 `tabtail-login.exe` 登录启动同路径代理，且保存的 enabled 必须为真。关闭自动恢复和卸载只删除归属命令仍完全一致的 HKCU Run 项。

默认三个快捷键均未绑定，由用户选择并验证；已知原生命令冲突和重复组合拒绝。通知采用系统通知区域气泡，兼容开发副本；显示／点击取决于 Windows 通知设置。原生成功与外观成功分别报告；首次 XAML 初始化可部分完成，后台同步重试，不把代理 ACK 当成成功。默认只启用图钉／锁图标，不预设未经视觉验收的彩色背景。

## v0.5.3 Shell 集合枚举

- 修复 `Count` 中存在空注册槽时 `Item(index)` 返回 `S_FALSE` 被误报为“Shell 集合在枚举时变化：函数不正确 (1)”的问题。实机诊断曾观测到 `Count=2`、`Item(0)=S_FALSE/null`、`Item(1)` 有效，而 `_NewEnum` 仅返回有效窗口对象。
- 改用 `_NewEnum` / `IEnumVARIANT::Next` 遍历有效对象，正确识别 `S_FALSE` 为枚举结束，不再要求返回对象数等于注册槽数量。仍检查前后集合长度变化、真实 HRESULT 错误、空对象、格式不符及 10000 项上限，失败时保留成功观察的标签。
- 新增 Shell collection 组件测试，模拟稀疏注册槽下 256 个预先打开对象的完整发现、身份顺序、空集合、COM 错误、中途变化及异常枚举器边界。
- 验证：272 项 Shell collection 检查及全部 11 组 CTest 通过。原路径升级实机代理到 0.5.3 后连续 8 次扫描均为 `scan_complete=true`、空 `warnings`，当前 1 个标签 `title_applied=true`、`runtime_applied=true`，应用错误为 0；未重启 Explorer。现有目录规则和默认设置保留。

## v0.5.2 Explorer 生命周期清理

- 独立于 Shell 集合完整性，按 PID、进程创建时间和进程退出状态清理确认结束的生命周期；整个 COM 扫描失败时也执行清理。查询权限或读取失败视为未知，不误删仍可能存活的标签。
- 临时漏扫保留标签 ID 和独立层级，`observed=false`，不再误报已应用或继续发送标题续订；重新观察到同一标签后恢复。重启后新进程、复用 PID/窗口不继承旧覆盖。
- 每轮扫描对同一进程生命周期只检查一次，支持启动时已打开大量标签。256 个模拟标签覆盖首次发现/应用、多个进程、连续不完整扫描、存活标签保留、进程退出和 PID/窗口复用；真实无窗口子进程验证存活、退出和创建时间匹配。
- 标题桥接继续校验同用户、同会话及进程身份。进程消失时改报“目标 Explorer 已退出或进程已更换”，身份无法验证时单独说明，不再把旧进程笼统报成其他用户会话。
- 验证：全部 10 组 CTest 通过；1220 项 tracker 检查、129 项 TUI 检查，包含清理后的选择和空列表详情刷新。真实进程测试使用无窗口子进程，不重启 Explorer。实机已有标签观察通过，256 标签为模拟生命周期/桥接测试，未据此宣称 256 个真实标签的性能已验收。
- 本机 0.5.1 到 0.5.2 升级需要保留原 EXE 路径；IPC 校验同一可执行文件，已驻留 DLL 只接受相邻的 `tabtail.exe`。`tools/update-agent.ps1` 使用原路径停止代理并仅更新 EXE、保留 DLL，再恢复原运行模式；错误时明确指出需要原命令路径。实机切换后已有标签 `title_applied=true`，Shell 集合扫描仍不完整，不据单标签成功宣称全局完成。

## v0.4.1 管理员终端重启支持（历史补丁）

`explorer restart --force` 允许从管理员终端执行，保留原有交互确认及 --yes 要求，仍只处理同 SID、同会话、系统路径匹配且创建时间复核通过的 Explorer。

结束 Explorer 之前准备备用启动上下文：普通终端保留原有启动路径；管理员终端优先复制当前桌面 Explorer 的普通权限主令牌，桌面已缺失时尝试 UAC linked filtered token。校验 SID、会话、未提权和普通桌面完整性级别，并检查 SeImpersonatePrivilege、准备用户环境。没有普通权限令牌时，如果经过校验的原桌面本身具有管理员权限，则保留原桌面权限；该分支使用当前同 SID、同会话的管理员进程创建后备 Explorer。没有可用上下文时在结束 Explorer 前退出。

继续优先等待系统自行重建 Shell；需要主动启动时，普通权限令牌分支使用 CreateProcessWithTokenW 和独立用户环境；原桌面已提权且无普通令牌时使用 CreateProcessW 保持原有权限。JSON 的 user_token_launch 表示是否实际通过普通权限令牌启动，launch_elevated 表示主动启动的权限，自动重建时为 null。该机制不支持替其他用户会话启动桌面。

新增 user_process 测试：用无窗口测试进程核验选定桌面上下文的提权状态、SID、会话和完整性级别；普通令牌可用时额外在普通权限子进程中测试普通启动路径。本机实测为调用者和原桌面都已提权、无可用普通令牌，保留原桌面权限的子进程启动通过。不重启真实 Explorer；分离 UAC 令牌分支和真实重启效果仍待人工确认。

### 标题更新流程

`controller` 为目标 Explorer UI 线程安装短时 WH_CALLWNDPROC 桥接，经注册消息触发 DLL。共享内存限制当前 SID，双方检查目标/发送方用户、会话、进程创建时间和相邻 EXE 路径。固定大小报文、版本、nonce、动作、深度与分隔符均校验；请求超时 4 秒。

DLL 在 UI 线程重新校验 GUID/子窗口，从对应 IBrowserHost 的 GetLocationItem 取得实时 IShellItem 和文件系统路径；虚拟位置保留普通显示名。probe 只读；首次 apply 在验证入口原始字节后用 MinHook 1.3.4 安装 SetFrameTitle detour。所有初始化均在 DllMain 之后进行。

有效策略按 frame + 原生 GUID 存储，每个标签有独立 depth，分隔符来自全局。detour 每次根据目标标签的当前位置重新计算，不复用其他标签的路径；异常或读取失败时透传 Explorer 传入标题。

代理每两秒补偿扫描并更新/续订约 10 秒租约。只有 UI 线程调用确认当前策略后才标记 title_applied；传输失败逐标签保留错误并重试。stop、agent stop 和正常退出尝试恢复 Shell 普通显示名；异常退出由 UI 线程计时器在租约过期后恢复。计时器不可用时拒绝发布策略。恢复失败会报告部分完成，UI 线程挂起时不保证及时恢复。

### 命令与安装

- `start`：启动观察代理，保存 enabled=true，显式开启定制并等待首次调用确认。无标签时返回 5，表示等待目标，不声称生效。
- `stop`：保存 enabled=false，恢复标题，保留观察代理与运行期覆盖。`agent stop` 退出代理并清除覆盖。
- `agent start`：始终先观察，即使配置仍为 enabled=true；不自动注入。登录自启尚未实现。
- `tabs probe <id>`：UI 线程只读原生位置探测，临时加载 DLL，不启用 MinHook。
- `tabs list/set/reset`：观察模式仍支持策略预览并返回 5；定制模式按逐标签 ACK 返回真实应用状态。全局修改不覆盖独立设置。
- installer 同时校验/复制 EXE 与 DLL，分发包携带 MinHook 许可证；doctor 提供系统 SHA、适配结论及 DLL 是否存在。

停止后 Hook 以透传状态保留，DLL 被 pin 至 Explorer 退出，避免补丁引用已卸载代码。不能热卸载，也不能覆盖/删除被 Explorer 加载的 DLL。卸载保留待删除清单；不自动重启 Explorer。不同路径的第二份 DLL 无法覆盖已存在的入口 Hook；请使用同一份安装操作，切换版本前需退出占用它的 Explorer。

## v0.3 真实标签观察与 CLI 策略管理（历史阶段）

新增：

- `ShellTabEnumerator`：通过 IShellWindows / IWebBrowser2 / IShellBrowser 获取每个独立浏览器子窗口，通过 IFolderView / IPersistFolder2 / IShellItem 解析真实路径与 Shell 显示名；验证目标属于当前用户、会话的系统 Explorer。
- `ShellTabTracker`：持有 COM 身份，稳定映射不透明 tab_id，桥接 TabRegistry；导航保留覆盖，位置读取失败清除旧路径，两次完整扫描缺失后清理标签。
- `agent start/stop/status/run`：后台无控制台的观察模式，按用户、会话、数据目录隔离，单实例；每两秒补偿扫描，并在标签请求前重新扫描。不同数据目录可用于独立测试。
- 用户受限命名管道：远程连接拒绝、同 SID/会话/EXE 验证、协议版本与请求 ID、1 MiB 报文上限、JSON 嵌套限制、读写超时与响应收据。
- `tabs list/set/reset`：列出真实标签，记录独立覆盖或恢复继承；JSON 包含真实路径、有效层级、来源、计算预览和 `title_applied=false`。
- 代理运行时接收 config set/reset 的默认值更新，不覆盖已有标签独立设置。卸载先停止对应观察代理。

`tabs set/reset` 和运行中代理的配置更新返回 5（部分完成），明确区分策略已记录与标题未应用。观察模式不改变配置中的 enabled，不注入 DLL，不导航或切换标签，不重启 Explorer。

本机只读探测：同一顶层窗口内观察到 5 个不同浏览器子窗口；连续两次扫描 COM 身份稳定，4 个文件系统目录与 1 个虚拟位置正确区分。端到端测试使用隔离的临时配置，为两个已观察标签分别记录数字和完整路径策略，验证全局继承、reset 与代理重启后旧 ID 失效；没有写入实际标签标题。

新增 tracker、IPC 和 agent 集成测试，连同已有 core、policy、CLI 共六组。通信测试包括超长帧、空闲客户端超时及后续请求恢复；16 个并发客户端状态请求通过。

限制：

- 观察用的 GUID 是代理生成的生命周期标识，不是 Explorer 原生 GUID，不能直接用于调用 SetFrameTitle。
- 尚无 DLL、标题 GUID 关联、真正标题应用与恢复、登录自启；P0 未完成。
- 当前 Shell COM 调用在代理 STA 内执行；I/O 超时不等于 COM 服务端调用具有硬超时，Explorer 无响应时 CLI 可能返回未确认结果。后续需要隔离或取消机制。
- COM 集合扫描无法保证捕获每一次中间变化。通过持有 COM 对象及子窗口验证降低串策略风险，但还需要生命周期事件订阅和更多系统组合测试。
- IPC 验证要求同一 EXE 路径；切换安装路径前先用原 EXE 停止代理。不承诺代理与新旧版本互通。

## v0.2 标签策略基础层

新增 `tabtail_policy` 静态库，只依赖 C++ 标准库；格式化模块不再读取整份 Config 或依赖 Win32、TOML、JSON。
