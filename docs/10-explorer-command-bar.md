# 10 资源管理器命令栏增强

在 Windows 11 资源管理器的原生命令栏逐项控制系统按钮的显隐，在右侧默认提供独立的「在此打开终端」按钮和「司南 ▾」菜单。菜单随当前标签和选区更新，集中提供标签、文件操作、目录与脚本、搜索与视图入口。设置入口为司南 GUI 的「外观 → 资源管理器命令栏」。

功能按下表交付。每阶段在真实 Explorer 窗口验证通过后，再将对应能力开放给设置页。

| 阶段 | 交付 |
| --- | --- |
| 0 · 验证原生集成 | 已通过左右栏挂载、重建、溢出和移除验收 |
| 1 · 控件显隐与终端 | 管理系统按钮、文字标签、分隔线，提供独立的终端按钮和恢复默认 |
| 2 · 司南菜单 | 接入标签、文件操作、目录与脚本、搜索与视图，实现选区条件、动态标签和剪贴板操作 |
| 3 · 新建模板与动作编排 | 扩展「新建」位置，提供模板名称规则、参数与图标选择、子菜单和可编辑预览 |
| 4 · 布局与菜单扩展 | 提供逐项左右摆位、系统按钮排序与独立恢复、间距、最近关闭列表、悬停菜单、Shell 上下文菜单和配置导入导出 |

## 阶段 0 · 验证原生集成

定位 `FileExplorerCommandBar` 和 `FileExplorerSecondaryCommandBar`，分别对应常驻的左、右命令栏。将原生 `AppBarButton` 加入对应的命令集合，验证右侧能容纳终端和司南两个入口。窗口变窄时验证原生溢出行为，并测试隐藏 `…` 后仍可通过设置页恢复入口。 [Explorer Command Bar 参考实现](https://windhawk.net/mods/explorer-command-bar)

复用司南布局适配的 XAML 树观察机制，通过 WinUI 公共接口访问命令集合。验证当前 Windows 11 x64 构建的布局适配能力及实际控件类型。若后续构建无法稳定覆盖已打开窗口和命令栏重建，再评估 `FileExplorerExtensions.dll` 的命令栏初始化路径，并校验模块身份、符号、入口指令与控件类型。 [现有布局适配](../src/hook/layout_dll.cpp) · [兼容性设计](05-symbol-compatibility.md)

**验收**　启用时已打开的窗口能添加测试按钮。切标签、切文件夹、创建新标签或窗口、改变主题和缩放后，左栏保留一个、右栏保留两个探针按钮。停用或代理租约失效后，测试按钮和事件订阅被清理。

**实测**　在已打开窗口、新窗口和新标签确认探针数量稳定，窄窗口触发原生溢出。在隐藏和恢复 `…` 前后确认命令仍可通过独立设置入口的路径恢复，阶段 1 接入设置页后验收完整操作。切换应用主题和显示缩放后，窗口实测 DPI 从 144 变为 120 并恢复为 144。主动移除与租约到期均恢复到左栏 33 项、右栏 5 项的初始集合。 [验收探针](../tools/layout_probe.cpp)

## 阶段 1 · 控件显隐与终端

| 设置 | 控件与行为 |
| --- | --- |
| 系统按钮 | 「新建」「剪切」「复制」「粘贴」「重命名」「共享」「删除」「排序」「查看」「…」「详细信息」各有独立开关。 |
| 上下文按钮 | 「解压全部」「设为桌面背景」「向左旋转」「向右旋转」各有独立开关。 |
| 按钮文字 | 「新建」「排序」「查看」「详细信息」可切换到仅图标，保留悬停提示、无障碍名称及原操作。 |
| 分隔线 | 支持隐藏「新建」后、「删除」后和「…」前的分隔线。整组控件都折叠时收起对应分隔线。 |
| 在此打开终端 | 独立放在右侧，用终端图标和「在此打开终端」悬停提示。点击在发起标签的实际文件系统目录打开终端。虚拟目录或搜索结果视图没有可用工作目录时禁用按钮。 |

系统控件的设置有「由 Windows 决定」和「隐藏」两种状态。恢复系统管理时撤销司南的属性覆盖，由 Windows 决定当前是否可见和可用。未选择图片时旋转按钮仍由系统收起，剪贴板没有可粘贴内容时「粘贴」仍由系统禁用。控件匹配优先使用稳定的自动化 ID、控件类型及所在命令栏，必要时结合已验证的资源标识。

设置页使用 TDesign 开关和分组，提供示意预览及「恢复默认」。总开关初始关闭，系统控件默认由 Windows 管理，启用功能后默认显示独立终端按钮。关闭总开关保留用户偏好，恢复默认则清除自定义值。应用到已打开窗口后，设置页显示已应用、等待窗口或当前版本不兼容。保存通知沿用 `vue-sonner`。 [外观设置页](../gui/src/views/AppearanceView.vue) · [终端动作](../src/platform/shell_actions.cpp#L102)

**验收**　逐项切换系统控件并恢复，检查「…」、右侧「详细信息」和条件出现的按钮。用包含中文和空格的两个目录验证独立终端按钮，切换标签后再次点击，确认终端工作目录对应新的发起标签。用窄窗口和键盘操作检查按钮入口及可访问性。

**实测**　在 Windows 11 的独立 Explorer 窗口确认 11 个系统按钮、4 个上下文按钮、4 处文字标签和 3 处分隔线的隐藏与恢复。压缩包和图片选中时验证对应上下文按钮。终端在两个包含中文和空格的目录中分别返回正确的工作目录，在 560 像素宽的窗口中可用键盘触发，在「此电脑」中置灰。WebView2 设置页验证了恢复默认、配置保存与应用状态。Release 构建、Vue 类型检查与 26 项 CTest 通过。

## 阶段 2 · 司南菜单和动态标签

| 菜单分组 | 动作 | 启用条件与状态 |
| --- | --- | --- |
| 标签 | 重开刚关闭的标签 | 沿用现有关闭记录与恢复逻辑。空记录时置灰。 |
| 标签 | 在新标签打开父目录 | 当前标签具有可用的文件系统父目录时启用。磁盘根目录置灰。 |
| 标签 | 固定标签、独立关闭保护、目录锁定 | 绑定发起标签。读取实际状态并显示勾选，按状态显示「取消固定」「取消保护」或「解锁目录」。 |
| 标签 | 合并重复标签 | 放在本组末尾，沿用现有同窗口合并和保留规则。 |
| 文件操作 | 新建文件、新建文件夹 | 在可用的文件系统目录中启用。新建文件复用输入文件名和「创建并打开」面板。 |
| 文件操作 | 发送到标签 | 有可传输的文件系统选区时打开现有目标选择面板。多选时可显示「发送 3 项到标签」。 |
| 文件操作 | 解压并定位 | 沿用现有归档与分卷识别规则。单选时可显示「解压 archive.zip 并定位」。 |
| 文件操作 | 复制选中项路径、复制当前目录路径 | 分别在存在可复制的选中路径、可用的文件系统目录时启用。 |
| 文件操作 | 复制选中项名称 | 有选区时启用，按选区顺序将带扩展名的文件名和文件夹名称逐行写入剪贴板。 |
| 文件操作 | 从剪贴板定位 | 与复制路径相邻。调用现有动作读取剪贴板路径，打开目录或定位文件。 |
| 目录与脚本 | 已配置的目录入口、PowerShell 动作 | 使用各自的配置名称。目录和脚本可在阶段 3 单独固定，调用时沿用现有目标及上下文。 |
| 搜索与视图 | Everything 搜索范围 | Everything 搜索可用时提供「当前文件夹」「全盘」两个单选项。沿用现有全局配置，默认「当前文件夹」。 |
| 搜索与视图 | 显示文件扩展名 | 勾选表示 Windows 当前的扩展名显示设置，执行后重新读取并显示实际状态。 |

标签管理沿用现有观察记录与标签身份，文件操作复用现有面板和动作。Everything 的查询词仍从资源管理器搜索框输入。文件夹大小通过原有「大小」列查看，选中项统计通过底部状态栏查看。 [标签恢复与合并](../src/agent/runtime.cpp#L489) · [文件动作](../src/agent/runtime.cpp#L576) · [新建文件面板](../src/panel/new_file.cpp#L339) · [目录入口](../src/agent/runtime.cpp#L460) · [文件扩展名设置](../src/platform/shell_actions.cpp#L260) · [大小列和选中项统计](09-explorer-folder-sizes.md#界面入口与扩展)

范围设置与「常规」页读写同一配置，保存后用于下一次查询。「当前文件夹」覆盖起始目录及子目录，「全盘」覆盖 Everything 索引。已有查询的即时刷新单独验证，原生搜索提交可稳定定位发起标签后，再接入原词重查。切换范围和连续编辑沿用现有查询失效机制。 [范围配置](../src/app/service.cpp#L326) · [原生搜索适配](../src/hook/everything_search.cpp)

菜单项保持固定顺序。打开菜单时读取当前标签和选区，选区事件触发可用状态和动态文字更新。动态标签使用选中数量、单个选中项名称或目录名称。菜单按可用宽度省略长文字，完整内容放入提示。多选标签优先显示数量，避免把多个路径塞入标题。

动作目录提供两个按上下文确定目标的可选动作，阶段 3 可加入菜单或固定。「在选中文件夹或当前目录打开终端」在单选文件系统文件夹时使用该文件夹，其他选区使用当前目录。独立的「在此打开终端」继续使用发起标签目录。「复制路径」在有选区时复制可用的选中项路径，空选区时复制当前目录路径。两项动作通过动态标签或提示展示当次目标，缺少所需路径时置灰。 [Windhawk 的 `%d_smart%` 和复制路径规则](https://windhawk.net/mods/explorer-command-bar)

为用户动作定义可配置的选区条件，在阶段 3 的动作编辑器中开放。支持任意选区、空选区、单选、多选、仅文件、仅文件夹，以及「全部选中项属于指定扩展名」。数量与类型条件可以组合。例如「用 VS Code 打开所选文件夹」要求单选且为文件夹，「压缩图片」要求全部选中项都是受支持的图片。条件不满足时，固定按钮默认置灰以保持位置，菜单项可选择置灰或隐藏。

复用 `actions.execute`、现有动作 ID 和选区读取能力。点击时锁定当次窗口、标签、目录或选区，执行前校验动作资格和目标。若目标已变化或关闭，结束该次操作并显示原因。文件操作和可能阻塞的 Shell 调用交由现有 Agent 或工作线程，Explorer UI 线程负责控件与菜单事件。 [动作目录](../src/app/actions.cpp) · [应用分派](../src/app/service.cpp#L76) · [选区事件](../src/agent/selection_summary.cpp#L208)

同一动作从固定按钮、子菜单和已配置的快捷键触发时，执行层使用同一套选区条件。菜单或按钮已显示的状态仅用于提示，执行时按实际目标重新校验。

Windhawk 的 `StartSelectionTimerIfNeeded` 每 250 毫秒检查选区，视图、选中数量与焦点项相同则跳过更新。多选时替换非焦点项可能漏过这次检查。其子菜单在打开时计算动态标签，快捷键直接分派动作，顶层按钮的选区筛选只作用于自身。这两处行为纳入司南的选区回归验证。 [命令栏参考实现](https://windhawk.net/mods/explorer-command-bar)

**验收**　在空选区、单个压缩包、多选和混选之间切换，检查标签和启用状态。覆盖数量与焦点项相同但选区发生变化的情况。用两个标签验证执行目标，检查固定、保护、锁定的状态及其取消操作，验证重开、同窗口合并和打开父目录，并覆盖空关闭记录和无父目录时的置灰状态。分别用文件路径、目录路径和无效剪贴板内容验证定位。检查扩展名勾选与 Windows 状态一致。两处不同目录放置同名文件，确认两种搜索范围返回预期结果，范围状态与司南 GUI 一致。用图片和文档混选验证按钮、子菜单和快捷键均拒绝只适用于图片的动作，并检查复制名称的逐行输出。

## 阶段 3 · 从模板新建与动作编排

- 在系统「新建」旁提供可选的「新建文件」快捷入口，继续使用现有面板。在司南菜单加「从模板新建」，并提供「新建」位置的快捷入口。启用模板快捷入口后默认与系统「新建」并列，可选替换原位置。模板菜单底部提供「打开模板目录」。 [现有新建文件](../src/panel/new_file.cpp) · [命令栏参考实现](https://windhawk.net/mods/explorer-command-bar)
- 打开模板菜单时枚举指定目录，按文件夹优先、名称自然排序，跳过隐藏项、系统项和 `desktop.ini`。识别到 PowerToys New+ 配置时，可采用其模板路径及隐藏扩展名、隐藏开头数字和替换变量的偏好。分别预览菜单名称与实际生成名称，例如「01 会议记录.md」可显示为「会议记录」。 [New+ 模板机制](https://learn.microsoft.com/windows/powertoys/newplus) · [命令栏参考实现](https://windhawk.net/mods/explorer-command-bar)
- 将模板复制到发起标签的目录。同名项自动编号，成功后在发起标签选中新项并进入重命名。日期、时间和父目录名称变量用于生成新建项的文件名。空文件、空文件夹、文件模板和文件夹模板分别接入并验证 Shell 撤销记录。 [现有 Shell 文件操作](../src/platform/shell_actions.cpp#L156)
- 用户可从动作目录选择内置动作、目录入口和已配置的 PowerShell 脚本，加入司南菜单、归入自定义子菜单或固定到原生命令栏。按动作 ID 保存引用，重命名后自动显示新名称，找不到来源时在设置里标明并禁用对应入口。 [现有动作目录](../src/app/actions.cpp)
- 应用入口支持「用指定应用打开选中项」和「在当前目录启动应用」。编辑器提供内置动作和应用程序选择器。参数来源可选当前目录、选中的文件夹优先、首个选中项、全部选中项、仅选中文件或仅选中文件夹。预览展示所选参数如何展开，覆盖含中文和空格的路径及多选参数。应用和脚本沿用同一份目录和选区数据。缺少必需参数时说明原因并中止启动。 [现有脚本上下文](../src/platform/shell_actions.cpp#L203) · [命令参数参考](https://windhawk.net/mods/explorer-command-bar)
- 应用与关联应用的脚本入口默认使用应用图标，支持识别应用执行别名和商店应用图标，并允许覆盖浅色、深色图标。图标无法读取时显示默认动作图标。 [图标参考](https://windhawk.net/mods/explorer-command-bar)
- 「司南 ▾」底部的「自定义命令栏」直接打开现有 WebView2 设置页的对应位置。把阶段 1 的示意预览扩展为可编辑预览，点击按钮可修改显隐、图标或标签，拖动可调整按钮与菜单项顺序，并支持复制菜单项。预览显示设置草稿，保存后应用到已打开的 Explorer。离开时提供保存、放弃和继续编辑。 [现有外观设置页](../gui/src/views/AppearanceView.vue)
- 固定按钮可独立启用动态标签。图标和按钮显示宽度保持稳定，长标签省略，提示保留完整文本。一键恢复默认可移除新增固定项。

**验收**　覆盖模板按钮并列、替换和恢复，检查名称排序、跳过项、New+ 设置与实际生成名称。验证模板在线增删、重名、复制失败及创建途中切标签。分别对空文件、空文件夹、文件模板和文件夹模板执行 Ctrl+Z，确认只撤销本次创建。用带中文和空格的路径验证参数预览与实际调用一致，并覆盖多选、必要参数缺失、应用执行别名、商店应用图标和主题切换。验证可选终端动作和「复制路径」在空选区、单选文件夹和多选时的目标，以及独立终端按钮的工作目录。验证命令栏直达设置、预览编辑、子菜单排序、复制、保存与放弃，确认重启后配置有效，引用删除后状态明确，窄窗口下动态标签占位稳定。

## 阶段 4 · 布局与菜单扩展

- 为「新建」至「查看」的常驻系统按钮提供排序、分隔线位置和间距设置，支持单独恢复系统按钮顺序并保留其他定制设置。条件按钮保留系统决定的位置，主题变化和关闭定制后能恢复既有布局。
- 固定入口逐项选择左栏或右栏，并分别调整顺序。沿用默认右侧的终端和司南菜单布局。用户可将「发送到标签」「解压并定位」等选区动作放到左侧，将终端和常用目录入口放到右侧。以真实窗口验证左右栏容量、窄窗口下的原生溢出及键盘可达性。 [Windhawk 左右栏参考](https://windhawk.net/mods/explorer-command-bar)
- 将「重开刚关闭的标签」扩展为可选的「最近关闭」子菜单，按时间倒序展示现有关闭记录，允许指定恢复其中一个标签。同名目录在提示中显示完整路径，确认恢复后移除对应记录。 [关闭记录](../src/agent/tab_tracker.cpp#L93) · [恢复确认](../src/agent/runtime.cpp#L474)
- 为司南的菜单按钮提供可选的悬停打开和延时设置，默认点击打开。鼠标离开、窗口失焦或控件销毁时取消等待，键盘仍可正常打开菜单。
- 提供可选的 Shell 上下文菜单入口。有选区时打开选区菜单，空选区时打开当前文件夹背景菜单。普通点击沿用原生右键菜单，按住 Shift 点击请求显示扩展命令。Shell 扩展子菜单与第三方菜单接管分别验收，按已验证的能力在设置页显示状态。 [原生 Shell 菜单参考](https://windhawk.net/mods/explorer-command-bar)
- 将「预览窗格」「详细信息窗格」「打开方式」「刷新当前视图」「文件夹选项」纳入可选内置动作。逐项验证发起标签和适用选区，用户可按需加入菜单或固定到命令栏。逐项启动程序、隐藏运行和临时提权留作应用入口的后续评估项。 [Windhawk 内置动作参考](https://windhawk.net/mods/explorer-command-bar)
- 支持导出命令栏布局、显隐、选区条件和动作引用。导入只更新设置草稿，在预览中标明缺失的目录、脚本或应用，用户修正后保存才应用。导出文件保留动作引用，目标机器上的实际路径由用户重新关联。

**验收**　把不同固定入口分配到两侧后重排，切换选区、标签和主题，调整窗口宽度，检查溢出、键盘可达性、系统菜单与动态按钮。单独恢复系统按钮顺序，检查其他设置仍生效。关闭多个标签后恢复列表中的非最近一项，确认目标目录及历史记录更新。验证悬停取消、普通点击与 Shift 点击、含 Shell 扩展的选区菜单及空选区背景菜单。用两个目录测试刷新动作的目标，并验证文件夹选项可打开。测试配置导出再导入、缺失引用和格式错误，确认保存前 Explorer 继续使用当前配置。

## 运行和配置

- 持久化到 `sinan.toml` 的 `[command_bar]`，包括总开关、终端开关、系统控件与标签的隐藏项、系统按钮顺序和分隔线、模板入口与名称选项、选区条件，以及包含参数来源、图标和左右位置的有序动作引用。缺少此配置节的旧版本按默认值读取。配置读取、保存和导入使用同一套校验，WebView2 通过现有设置桥报告应用结果。 [配置入口](../src/config/config.cpp) · [设置桥](../src/ui/webview_main.cpp)
- 以命令栏实例管理事件和属性覆盖。集合发生变化时合并更新并投递至该控件的 UI 线程，同一窗口与控件重复挂载结果相同。撤销时移除司南自有按钮，恢复原局部属性或其系统绑定，并释放事件、弱引用和计时器。停止代理、布局重建及版本适配校验失败均纳入验收。
- 选区状态按实际需要读取，优先复用事件和菜单打开时刷新。用无窗口、单窗口、多窗口和大批量选区测量空闲 CPU、工作集、命令栏刷新及菜单打开耗时，并与关闭功能时的基线比较。关闭 WebView2 设置页后，通过 Agent 继续应用已保存的配置。
